AIに仕事を任せる前に決める3つの境界線

AIエージェントに実務を任せると決めたとき、最初に詰まるのは「どこまで任せるか」です。ここを曖昧にしたまま走らせると、いつか取り返しのつかない操作をやられます。この記事では、実際にAIを実行部隊にして会社を運営している中で使っている権限境界の決め方と、そのままコピーして使えるテンプレートを無料で公開します。

結論:この3つだけは、絶対に人間が握る

業種や規模を問わず、以下の3つはAIに最終実行させないのが安全だと考えています。逆に言えば、この3つ以外は思い切って任せてよいという線引きにもなります。

1. お金が動く操作

支払い・送金・購入の確定・契約の締結・価格変更の適用。AIには見積もりの比較や申込内容の下書きまでをやらせ、最後に確定させるのは人間にします。金銭は取り消しに手間とコストがかかり、失敗が一番はっきり損害になる領域です。

2. 外に出るメッセージの最終送信

メール送信・SNSへの投稿・問い合わせフォームの送信。AIは下書きまで、送信ボタンは人間が押します。一度外に出た文章は取り消せません。可能なら運用ルールだけでなくツールの権限自体を「下書きのみ・送信不可」に設定しておくと、うっかりが構造的に起きなくなります。

3. 認証情報の取り扱い

パスワード・APIキー・トークンの入力、新規アカウントの作成、外部サービスへの権限付与。ここをAIに渡すと、他の境界線をいくら決めても意味がなくなります(権限さえあれば1と2も実行できてしまうため)。

業種によって足すもの:上の3つは普遍的な部分です。実際にはここに業種固有の項目を足します。たとえば医療なら有資格者の判断が必要な領域、士業なら顧客の機微情報へのアクセス、受託開発なら本番環境への変更。「これをAIがやったら事故になる」という操作を1つ2つ書き足してください。

そのまま使えるテンプレート

Claude Codeなどのコーディングエージェントを使っている場合、プロジェクト直下の CLAUDE.md に以下を書いておくと、毎回説明せずに済みます。{{ }} の部分だけ自分の事業に置き換えてください。

# {{事業名}} — AI運用ルール

## 権限境界(絶対に譲らないルール)

以下の操作は必ず人間が行い、AIは直接実行しない。
AIができるのは下準備(調査・下書き作成・提案)までとする。

1. **お金が動く操作**: 支払い、送金、購入確定、契約締結、価格変更の適用。
   → AIは見積もり・比較・申込内容の下書きまで。
2. **対外的なメッセージの最終送信**: メール送信、SNS投稿の公開、フォーム送信。
   → AIは下書きまで。送信・公開ボタンは人間が押す。
3. **認証情報の取り扱い**: パスワード・APIキー・トークンの入力、
   アカウント作成、外部サービスへの権限付与。
4. **{{業種固有の項目。例:本番環境への変更 / 顧客の機微情報へのアクセス}}**

上記以外の日常業務(調査、下書き作成、優先順位付け、
コンテンツのテーマ決定など)はAIの裁量で進めてよい。

## 判断の記録

AIが行った判断は {{記録先のファイル。例: decision_log.md}} に追記する。
形式は「現状 → 選択肢 → リスク → 決定 → 次アクション」。
承認が必要な事項は、AIが明示的に「承認をお願いします」と伝える。

なぜ「判断の記録」までセットなのか

境界線を決めるだけでは足りません。AIが何を判断して、人間が何を承認したのかが後から辿れる状態にしておく必要があります。理由は2つあります。

1つは実務的な理由です。任せる範囲を広げていくと、必ず「これ誰がどういう理由で決めたんだっけ」が起きます。記録がないと、同じ検討を何度もやり直すことになります。

2つ目は責任の所在です。AIエージェントの利用が広がるにつれ、「AIが勝手にやった」という説明が通らない方向に環境が動いています。実際に、AIが自律的に行動したことを免責の理由として認めない立法例も出てきています。そうなると、導入した側がどう監督していたかが問われます。承認ゲートと判断の記録は、そのときに「きちんと監督していた」と示せる材料そのものです。

逆に言うと、ここを整えておけば、AIに任せる範囲は安心して広げられます。うちの場合、この設計にしてから、記事の執筆から公開までを人の確認なしで回せるようになりました。
